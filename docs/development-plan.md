## First implementation task after this phase

**Build a small, model-free MLX fixed-block append/lifetime experiment, not a production runtime package.**

1. Use 256-row synthetic latent/RoPE/indexer blocks, one stream, and a small admitted pool. Append through many boundaries and gather selected rows across blocks.
2. Compare completion disciplines on identical work: output-only evaluation as a diagnostic control; synchronous `mx.eval` of all changed state and outputs; and ds41f-style `mx.async_eval` of all changed state/outputs, `mx.eval` of the input token/control dependency, then `mx.synchronize(stream)` before commit or buffer reuse. Evaluating the control token alone is not an all-state completion fence. Drain every variant before teardown.
3. For those variants compare private tails against intentionally retained lazy outputs and retained views. Hold references for a bounded interval, then drop them and measure recovery. Check values **and which completion/release boundary actually permits bounded backing and scratch reuse**, including whether synchronization without dropping aliases is insufficient. Use allocation instrumentation for backing identity if available; Python `id()` alone is insufficient.
4. Distinguish active/live bytes, allocator cache, RSS and peak; release scratch at the tested safe boundary and run close/recreate repeatedly. Keep allocator policy and workload comparable rather than masking growth by clearing the pool at every step.
5. Run this bounded experiment and small exact-weight/native score/sparse-MLA smoke comparisons on candidate MLX 0.32.2 and 0.32.3 builds. Rebuild native extensions per candidate; check supported dimensions, including selected-row `K >= 16`. Select one baseline MLX build in M1 and confirm/pin it at M2 entry. If an optional native route cannot be built/smoked, leave it disabled with an explicit fallback decision rather than assuming compatibility; required exact weight kernels must pass.
6. Decide between private evaluated MLX tails, bounded tail-page copying, and a minimal native storage boundary. Record the chosen completion discipline, build and storage decision in a short note and stop; do not build a general cache or evidence framework first.

This is a bounded answer to the highest-risk interface. Exact operator adaptation and normal model loading follow it within M1/M2. It needs no model download.

## Explicit deferrals

Whole-expert FP8 expansion/LRU caches, affine4 or MXFP4 replacements, scale folding/re-quantization, indexer compression, RoPE quantization, dynamic cache precision conversion, page-native sparse fusion, aggressive `mx.compile` capture of mutable sessions, multistream overlap, token lookahead, broad prompt-prefix sharing/persistence, MTP, speculative trees, general server/batching, and benchmark/release formalism.

Small exact acceleration may be promoted later only with a concrete profile and stable memory. No approximate weight profile is needed to call the core useful.
